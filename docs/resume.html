Selected work

  • Keel (current project; fourth iteration of my architecture thinking) — a platform kernel that company software would run on. One service where every action by a person, a backend service, or an AI agent has to be explicitly authorized for that company and then recorded as evidence. Covers identity, permissions, company data, connections to outside systems, and calls to AI models through the same audited path, with the rules checked against a formal contract written in Zig and stored in PostgreSQL. Apps and company-specific products sit on top as data and clients. No customers or shipped product yet; it is the architecture I now consult on.
  • Substrate OWASP LLM Top 10 case studies — ten live slices, one per risk (LLM01–LLM10), showing how an authorization layer contains these risks: an unattested model refused before it runs, attacker-written text that cannot execute, a published system prompt that buys an attacker nothing. They test the same authorization-and-evidence ideas as Keel.
  • 78 websites in about 5 weeks from an AI build pipeline; no paying client, one site hosted for a friend. Throughput lesson: the build outpaced a one-person sales motion, so the bottleneck moved downstream (website-builder-test, life-saver-biz arc)
  • caa-core@0.2.0 — published canonical agent framework (while-loop pattern) with span-based SQLite tracing and a Svelte 5 trace UI for inspecting agent runs
  • Methodology artifacts — MAOD / MOAD AI-orchestrated development methodologies (process constraints, slash commands, prompt templates) and pi-harness Stoic Architecture, workflow tooling that forces explicit deterministic-vs-non-deterministic boundary decisions before implementation
