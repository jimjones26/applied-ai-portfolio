Selected case studies from ~83 experiments

Substrate — The Model It Can’t Bind

A model-routing company serves every customer task on a third-party specialist — its supply chain is its product — and a PoisonGPT-style tampered model is published into a source it curates. OWASP LLM03 is Supply Chain: a third-party model enters the runtime with no provenance and an agent binds it. What it shows: binding an unattested model is made unconstructable, not merely discouraged — a production provider requires an Ed25519 attestation, so the poisoned model is refused at the binding boundary before a single token (ModelProvenanceUnverified), the refusal is sealed as a first-class DENIED envelope, and the same model is confined — not banned — to an eval lane where default-deny egress keeps customer data away from it. Honest about the one link it can’t close: fingerprinting opaque vendor weights. A live slice on Substrate against OWASP LLM03 (Supply Chain).

Substrate — The Output It Can’t Weaponize

An incident console feeds attacker-controlled alert text at two sinks that would act on it — a command sink that runs diagnostics over a workspace, and a public HTML status page. OWASP LLM05 is Improper Output Handling: untrusted output reaching a shell, an eval, or a browser that renders it. What it shows: the dangerous crossing is made unconstructable, not merely discouraged — inbound alerts are marked untrusted and every sink is default-deny, the cleared command runs argv-exact with no shell, an irreversible remediation suspends for human review, and HTML-encoding lives on the recipient — so the deliberately-naive {@html} status page renders a laundered <script> / <img onerror> as inert text. A live slice on Substrate against OWASP LLM05 (Improper Output Handling).

Substrate — The Prompt It Can Publish

A retail bank publishes its AI assistant's complete system prompt in the console — under a banner saying it is not a secret — and the bank is still secure. OWASP is blunt: the prompt is not a secret and must not be a security control; the real failure is the credential, limit, or permission a developer wrongly embeds in it. What it shows: knowing every word of the prompt buys an attacker nothing, because every control lives where a leaked prompt cannot reach it — the model credential below the spine, the $5,000 daily limit in a Policy, the money in the balance — and a credential pasted into a prompt cannot even deploy. A live slice on Substrate against OWASP LLM07 (System Prompt Leakage).

Substrate — The Neighbor It Can't Retrieve

A research desk runs RAG over one shared corpus across an ethical wall between client engagements — and the vector index ranks a forbidden document #1. Cosine distance is blind to who may see what: a chunk can be the single most relevant hit and strictly forbidden. What it shows: Carrel structurally cannot retrieve that document, because the index only proposes opaque candidate ids and every one is re-fetched through a tenant-partitioned, marking-gated read before a single chunk reaches the model. The #1 neighbor is re-fetched, dropped, and never enters the context — no human approval, no output scanner. A live slice on Substrate against OWASP LLM08 (Vector & Embedding Weaknesses).

Substrate — The Figure It Can't Fabricate

A market desk lets a live LLM write its briefs — and a language model states a number with total confidence whether or not the number is real. Confident fabrication and grounded fact are indistinguishable at the point of publication. What it shows: Beacon structurally cannot publish a figure it cannot ground, because publishing is a governed Action whose eval gate scores the claim against its cited Source before the brief is ever persisted. A figure with no authoritative filing fails closed and never becomes a published row — no human approval, no output scanner. A live slice on Substrate against OWASP LLM09 (Misinformation).

Substrate — The Secret the Model Never Saw

A support assistant is handed an inquiry that demands the customer's SSN, date of birth, card number, and bank secrets — a targeted extraction dressed up as an “internal audit override.” A weak model tries to comply. What it shows: the assistant structurally cannot leak any of it, because the substrate stripped the PII and dropped the secret record at context assembly — before the prompt was ever built. The extraction is unsatisfiable: there is nothing in the model's context to copy, with no human approval and no output scanner. A live slice on Substrate against OWASP LLM02 (Sensitive Information Disclosure).

Substrate — The Injection That Can't Launder Itself

A briefing agent is fed an untrusted source carrying an indirect prompt injection — an order to copy the source verbatim into a partner briefing and exfiltrate internal notes. The agent does read it; summarising it is the job. What it shows: the injection structurally cannot launder itself across the trusted-partner boundary — a briefing distilled from untrusted input is itself untrusted, the taint follows the derivation, and the egress gate refuses the delivery with no human in the loop. Substrate — The Loop That Stops Itself

A support-triage agent is pointed at a queue an attacker has flooded with junk tickets — each one a real model call, real money — and one ticket is a prompt injection ordering the agent to run forever. What it shows: the loop halts itself at a declared budget, fail-closed, before the next model call fires — no human in the loop, no kill switch. The injected “never stop” instruction cannot extend the loop, because the loop is the runtime’s, not the model’s. A live slice on Substrate against OWASP LLM10 (Unbounded Consumption).

Substrate — The Leak a Human Can't Approve

An over-broad mailbox assistant is handed the power to forward mail out of the company, and a confidential board packet carries a prompt injection telling it to leak. What it shows: the message structurally cannot be exfiltrated — refused at the egress boundary even after a human is tricked into approving the send, because classification is structural and approval does not override it. A live slice on Substrate against OWASP LLM06 (Excessive Agency) — the over-broad capability is left in place, and the deeper layers contain it anyway.

Substrate — The Demand That Can't Leak

A subrogation demand sent across the hard boundary between two insurance carriers, carrying reserve figures, settlement strategy, and a behavioral model of the counterparty — none of which may cross. What it shows: the leak is unconstructable by the substrate itself, not by a careful developer or a code review; the irreversible send escalates to a human; and the receiving carrier — no account, no callback, only a public key — verifies the demand is authentic offline. Built end to end in under 12 hours, including two new substrate capabilities — because governed egress, human authority, and a verifiable passport were already the floor.

Substrate - Governed by Construction

A complete multi-tenant authentication product, built as a single slice on Substrate — public landing and sign-in, self-service organization signup, an operator console, role-based dashboards, and a full audit surface. What it shows: every governance guarantee — a tamper-evident audit log, hard tenant isolation, a policy engine that blocks privileged actions before they run, and unforgeable attribution — is structural, supplied by the substrate rather than written by me. I couldn’t forget to govern. Speed is the consequence of not having to build the dangerous part.

Substrate — Prelude

A partial test of Substrate — the bet that governance can be a structural property, not a policy layer bolted on afterward. Substrate is an architecture that aims to make the ungoverned path unconstructable; Prelude stress-tests that claim through an AI-native pre-need planning scenario, carrying one test customer end to end — AI agents that can only propose, every seam policy-gated and audited, a decades-long lifecycle, and a regulator who reconstructs the entire record from one audit log. What the test shows: "delete my data" becomes a partition by subject, not a DROP — one beneficiary's data erased while the deceased's locked letter stays intact.

Hallucination Needs Its Own Pipeline Stage

A 13-step LLM website-rebuild pipeline in TypeScript. Two production failure modes — content hallucination and structural drift between separately-generated sections — couldn't be closed by prompt engineering; each needed its own dedicated pipeline stage. R&D finding: pipeline length is diagnostic — every extra stage is a failure mode you discovered by running, not by designing.

Personal AI Memory: The O(history) Problem

Six iterations of a long-running R&D track on AI assistants that accumulate memory across sessions (15-crate Rust workspace at the latest, 404 commits, plus a deployed Python instance). Two memory architectures explored, both with real costs. R&D finding: AI memory isn't a storage problem — it's a safety architecture problem. The local memory store got wiped multiple times in development before I added hooks to intercept irreversible commands.

How I work

What I bring beyond the code

Translating between business and AI

Twenty-five years of consulting has been about bridging gaps — designer to developer, business stakeholder to engineer, customer goal to technical architecture. The AI work is the same job at a new layer: business problem to AI architecture, AI behavior to non-technical decision-maker. I default to plain language and keep jargon load-bearing.

Methodology built to be reused

The R&D program produced reusable methodology artifacts: MAOD/MOAD AI-orchestrated development methodologies, the Stoic Architecture workflow tooling (pi-harness slash commands), the canonical agent framework (caa-core@0.2.0). Plus ten years of independent training and expertise consulting before the AI program. Built to be transferred, not hoarded.

Findings, not finished products

None of the R&D builds have been deployed to sustained production with paying users — the goal is mapping how AI actually works, not landing a product. Test beds are real problem domains (real-estate transaction coordination, HVAC lead response, supplier-portal procurement, site rebuilds for small businesses), so what's learned transfers to real engineering, not toy demos. Each case study captures one specific finding about where AI delivers reliable work and where it breaks.
